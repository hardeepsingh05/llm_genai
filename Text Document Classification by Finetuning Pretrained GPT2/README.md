# Text Document Classification by Fine-Tuning GPT-2

This project experiments with adapting the pretrained GPT-2 124M language model for supervised Youtube comments(sentiment) text classification. The accompanying notebook prepares a labeled text dataset, reconstructs the GPT-2 architecture, loads pretrained GPT-2 weights, replaces the language-model output layer with a classification head, and fine-tunes selected model layers.

The notebook currently works with text stored in a `Comment` column and integer labels stored in an `Encoded_Sentiment` column. Although the project is described as document classification, the same pipeline can be adapted to comments, messages, reviews, or other short text documents.

## Project Workflow

1. Import the Python dependencies and select the available processing device.
2. Download and load the source dataset through KaggleHub.
3. Inspect the dataset structure, text lengths, missing values, class counts, and duplicates.
4. Clean the text by normalizing case and removing links, mentions, hashtags, punctuation, digits, and other special characters.
5. Remove duplicate rows and create a balanced dataset by sampling each class to the size of the smallest class.
6. Shuffle and split the data into training, validation, and test sets.
7. Replace missing text values and save the prepared splits as CSV files.
8. Tokenize the text with the GPT-2 tokenizer and create padded PyTorch datasets and DataLoaders.
9. Define the GPT-2 building blocks, including layer normalization, GELU, feed-forward layers, masked multi-head attention, transformer blocks, and the complete model.
10. Load the published GPT-2 124M checkpoint parameters into the PyTorch model.
11. Freeze the pretrained parameters, replace the language-model output layer with a three-class classification head, and unfreeze the final transformer block and final normalization layer.
12. Measure baseline loss and accuracy, fine-tune the model with AdamW, and track training and validation metrics.
13. Plot loss and accuracy histories, evaluate the model on all data splits, classify sample text, and save a model checkpoint.

## Main Files

The CSV files and checkpoint are generated during the workflow and may be stored in a different working directory depending on where the notebook kernel is launched.

## Model Configuration

The experiment uses the GPT-2 124M configuration:

- Vocabulary size: 50,257 tokens
- Context length: 1,024 tokens
- Embedding size: 768
- Attention heads: 12
- Transformer layers: 12
- Dropout rate: 0.1
- Query, key, and value biases: enabled

The classification head produces three output logits. The predicted class is the index with the highest logit after the final input token.

## GPT-2 Checkpoint

The notebook expects the GPT-2 124M checkpoint files under a local `gpt2/124M` directory. The required files include the model checkpoint, `hparams.json`, `encoder.json`, and `vocab.bpe`. The notebook also contains utilities for downloading and loading these files from the public GPT-2 checkpoint location.

Downloading model files requires network access. KaggleHub also requires access to the requested dataset and may require Kaggle authentication or configuration in the local environment.

7. Keep the generated checkpoint if the trained model needs to be restored later.

## Notes and Limitations

- Several paths in the notebook are machine-specific absolute Windows paths and may need to be updated on another computer.
- The notebook uses a maximum sequence length of 1,024 tokens, which can require substantial memory, especially during fine-tuning.
- The current classification setup assumes three target classes and an `Encoded_Sentiment` label column.
- Balancing by downsampling discards examples from larger classes. Alternative strategies include class-weighted loss or oversampling.
- The notebook recreates GPT-2 and loads the original checkpoint rather than using a higher-level pretrained-model library.
- Model quality depends on the source dataset, label quality, split strategy, training duration, and available hardware.

## Purpose of the Experiment

The main purpose is educational and experimental: to show how a pretrained causal language model can be repurposed for classification by adding a task-specific output head and fine-tuning a small portion of the transformer. The notebook also demonstrates the supporting data pipeline required to move from raw labeled text to a saved, reusable classifier.
